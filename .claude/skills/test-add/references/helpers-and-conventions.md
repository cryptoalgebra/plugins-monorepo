# Shared helpers and time/gas conventions

Referenced from `test-add`'s SKILL.md. Read this before reaching for a generic EVM time-travel helper, before hand-rolling tick-spacing or fee-tier math, or before comparing a struct-shaped contract return value.

## Shared helpers (both styles)

- `test-utils/utilities` and `test-utils/externalFixtures` (e.g. `tokensFixture`) are the shared helpers — import from there instead of reimplementing, regardless of which style the file otherwise follows. `utilities` exports more than just `encodePriceSqrt`: `expandTo18Decimals`, `MaxUint128`, `MIN_TICK`/`MAX_TICK`, `getMinTick`/`getMaxTick`, `getMaxLiquidityPerTick`, `FeeAmount`/`TICK_SPACINGS`, `PLUGIN_FLAGS`, `getCreate2Address`, `encodeCallback` — check there before hand-rolling tick-spacing or fee-tier math (used e.g. in `packages/default-plugin/test/AlgebraPool.gas.spec.ts:12-24`).
- Wrap gas-sensitive calls with `snapshotGasCost(...)` from `test-utils/snapshotGasCost` (see `packages/limit-order/test/LimitOrderPlugin.spec.ts:183`).
- `test-utils/checkTimepointEquals` compares a timepoint-shaped return value (`{initialized, tickCumulative, blockTimestamp}`) against an expected object — needed because ethers' returned struct extends `Array`, which breaks a plain `.to.deep.eq(...)`. Only `packages/volatility-oracle/test/VolatilityOracle.spec.ts` uses it so far, but reach for it (or something shaped like it) any time a test needs to compare a struct-shaped contract return value.
- `.to.matchSnapshot()` (from the same jest-snapshot plugin `snapshotGasCost` uses internally) is an established alternative to hand-deriving an expected value for a pure-computation result that would be tedious or brittle to write out — see `packages/dynamic-fee/test/AdaptiveFee.spec.ts:94` and `packages/volatility-oracle/test/VolatilityOracle.spec.ts:616` for non-gas uses. Snapshots live in `test/__snapshots__/<file>.spec.ts.snap` and are created automatically on first run; there's no dedicated "update snapshot" script in this repo, so to force regeneration, delete (or hand-edit) the relevant entry in the `.snap` file and re-run the test.
- Contract *types* (when a file does import typed contracts, e.g. for a return-value annotation) always come from the package's own generated `../typechain` — never hand-written interfaces.

## Time-dependent tests and gas snapshots

- **Advancing time**: this repo never uses `evm_increaseTime` or hardhat-network-helpers' `time.increase`. `MockTime*` contracts (pools, plugins, oracles) expose their own `advanceTime(seconds)` that bumps an internal mock clock, and when a pool and its plugin each track time separately, both need advancing together, e.g. `packages/default-plugin/test/AlgebraPool.gas.spec.ts:91-94`: `await pool.advanceTime(secs); await plugin.advanceTime(secs);`. Look for an `advanceTime` method on the mock contracts already in play before reaching for a generic EVM time-travel helper.
- **`[ @skip-on-coverage ]`** appears in several gas-cost test titles across the repo (`packages/default-plugin/test/AlgebraPool.gas.spec.ts`, `packages/dynamic-fee/test/AdaptiveFee.spec.ts`, `packages/volatility-oracle/test/VolatilityOracle*.spec.ts`), signaling "skip this under coverage instrumentation, the gas numbers are meaningless there." It's only actually *enforced*, though, where a package has a `.solcover.js` with `mocha: { grep: '@skip-on-coverage', invert: true }` — as of writing that's `packages/alm/.solcover.js` and nowhere else. If you add a gas-cost test in a package without that config, including the tag is harmless (and consistent with the rest of the repo) but won't itself make `npx hardhat coverage` skip it.
