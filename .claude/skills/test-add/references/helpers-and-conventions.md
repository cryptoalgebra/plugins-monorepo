# Shared helpers and time/gas conventions

Referenced from `test-add`'s SKILL.md. Read this before reaching for a generic EVM time-travel helper, before hand-rolling tick-spacing or fee-tier math, or before comparing a struct-shaped contract return value.

## Shared helpers (both styles)

- `test-utils/utilities` and `test-utils/externalFixtures` (e.g. `tokensFixture`) are the shared helpers — import from there instead of reimplementing, regardless of which style the file otherwise follows. `utilities` exports more than just `encodePriceSqrt`: `expandTo18Decimals`, `MaxUint128`, `MIN_TICK`/`MAX_TICK`, `getMinTick`/`getMaxTick`, `getMaxLiquidityPerTick`, `FeeAmount`/`TICK_SPACINGS`, `PLUGIN_FLAGS`, `getCreate2Address`, `encodeCallback` — check there before hand-rolling tick-spacing or fee-tier math (used e.g. in `packages/default-plugin/test/AlgebraPool.gas.spec.ts:12-24`).
- `test-utils/consts` holds the shared constants — `ZERO_ADDRESS` and `TEST_POOL_START_TIME`. Import from there rather than declaring your own; several fixtures predate it and redeclare `ZERO_ADDRESS` locally, which is not a pattern to copy.
- **Import shared helpers by the specifier the package's own specs already use**, and check a sibling file rather than typing one from memory. The `test-utils` package has been renamed in the past, so branches disagree about whether it is imported bare or under a scope, and a path that resolves on one branch fails on another. Relative paths into the package (`../../test-utils/externalFixtures`) also appear and work.
- Wrap gas-sensitive calls with `snapshotGasCost(...)` from `test-utils/snapshotGasCost` (see `packages/limit-order/test/LimitOrderPlugin.spec.ts:183`).
- `test-utils/checkTimepointEquals` compares a timepoint-shaped return value (`{initialized, tickCumulative, blockTimestamp}`) against an expected object — needed because ethers' returned struct extends `Array`, which breaks a plain `.to.deep.eq(...)`. Only `packages/volatility-oracle/test/VolatilityOracle.spec.ts` uses it so far, but reach for it (or something shaped like it) any time a test needs to compare a struct-shaped contract return value.
- `.to.matchSnapshot()` (from the same jest-snapshot plugin `snapshotGasCost` uses internally) is an established alternative to hand-deriving an expected value for a pure-computation result that would be tedious or brittle to write out — see `packages/dynamic-fee/test/AdaptiveFee.spec.ts:94` and `packages/volatility-oracle/test/VolatilityOracle.spec.ts:616` for non-gas uses. Snapshots live in `test/__snapshots__/<file>.spec.ts.snap` and are created automatically on first run. To regenerate, run the suite with `UPDATE_SNAPSHOT=1` (or `--update`) — but read the entry in `references/gotchas.md` first, because that flag deletes every snapshot the run did not touch and so must never be combined with `--grep` or a single spec file. Hand-editing the `.snap` entry is the right move only when a full run is not available.
- Contract *types* (when a file does import typed contracts, e.g. for a return-value annotation) always come from the package's own generated `../typechain` — never hand-written interfaces.

## Driving pool state from a test

Some behavior can only be reached by moving the pool underneath the contract under test, rather than by calling that contract — a price crossing a position's range, fees accruing, a tick being crossed. Don't hand-roll a swap for this.

- `algebraPoolDeployerMockFixture()` (`test-utils/externalFixtures`) already returns a **`swapTargetCallee`** — an Algebra-core `TestAlgebraCallee` — alongside the pool and tokens. It is the repo-wide way to act on a real pool from a test: `mint(pool, recipient, tickLower, tickUpper, liquidity)` to seed liquidity, and `swapToLowerSqrtPrice(pool, targetSqrtPrice, recipient)` / `swapToHigherSqrtPrice(pool, targetSqrtPrice, recipient)` to push the price to a target and stop there. Both are used heavily in `packages/limit-order/test/LimitOrderPlugin.spec.ts` and `packages/default-plugin/test/AlgebraPool.gas.spec.ts`. Approve the tokens **to the callee**, not to the pool — the callee is what calls `transferFrom`.
- The two `swapTo*SqrtPrice` calls consume as much input as the target price requires, which for a swap that has to cross a whole tick's liquidity can approach the entire position. Fund the swapper generously rather than sizing the budget tightly; the swap stops at the target price regardless.
- **Picking the target price**: `encodePriceSqrt(a, b)` from `test-utils/utilities` covers simple ratio targets. For a target defined relative to a *tick* (just past a position's bound, exactly on it, or midway inside it), get the exact value from a `contracts/test/` harness that exposes the package's own tick math — hand-computing a sqrt price in TypeScript drifts from what the contract will compute. Note that "exactly on a tick boundary" and "a fraction of the way into a tick" are genuinely different cases and a bug can reproduce at one and not the other; a real swap or oracle-derived price almost never lands exactly on a boundary.
- Swapping through a pool whose plugin mock doesn't implement the whole hook surface needs `pool.setPluginConfig(0)` first — see `references/gotchas.md`.

## Asserting against values the contract computes

- **Read a constant from the contract instead of copying its literal into the test.** If a test needs a contract's buffer, threshold, or minimum, call the public getter (`await contract.SOME_CONSTANT()`) rather than repeating the number — a copied literal silently stops matching when the constant is tuned. Widening a `private constant` to `public` for this is an accepted, no-op change in this repo, the same way widening `private` to `internal` for a harness is.
- **Don't assert an exact value the contract doesn't actually guarantee.** Where an implementation deliberately withholds a rounding buffer, rounds down, or leaves dust, assert the bound (`to.be.at.most(buffer)`, a tolerance derived from the input size, or `to.be.approximately(expected, delta)` — the established form for fixed-point results, e.g. `packages/sliding-fee/test/SlidingFee.spec.ts`) and say in a comment why the slack exists. An `to.equal(0n)` on a quantity the contract only promises to keep *small* is a test that will fail later for a correct implementation.
- Where a value is genuinely unchanged by the operation under test — an untouched position's stored ticks and liquidity, a field an unrelated call must not write — assert exact equality against the value captured before the operation. That pairing (exact equality for what must not move, bounded assertions for what rounds) is what makes an invariant test meaningful.

## Cases driven by recorded data

Some suites are regression corpora rather than hand-written cases: a JSON file next to the spec holding transactions recorded from a live deployment, imported and expanded into one `it` per record, with the originating transaction hash in the title so a failure names the exact trade it came from (`packages/alm/test/almRebalances.json` and `AlmPlugin.spec.ts`). Two things follow. Add new cases by appending records to the JSON, not by writing another hand-rolled `it` beside the loop. And check how the loop selects records before assuming a new one runs. There is no `.slice(0, N)` cap left in the repo, but `packages/alm/test/AlmPlugin.spec.ts` filters against a `HELD_OUT` set of transaction hashes the contract reproduces differently, whose behavior is pinned separately instead. A record that lands in a set like that is excluded, not failing, and the exclusion should stay deliberate: if you add records, say which selection they fall under.

## Suites that build heavy on-chain state

Filling a large structure (a ring buffer with tens of thousands of slots, a long price history) needs three things together, and they are easy to get partly right:

- A **batching method on the `contracts/test/` harness** that advances many entries per transaction. Doing it one call at a time from TypeScript is orders of magnitude slower.
- **`this.timeout(...)` on the `describe`**, which requires the non-arrow `function () { ... }` form — inside an arrow callback `this` is not the mocha context and the timeout silently does nothing. See `packages/volatility-oracle/test/VolatilityOracle.spec.ts`.
- **A raised wallet balance** when the loop's total gas exceeds default funding: `await ethers.provider.send('hardhat_setBalance', [wallet.address, '0xFFFF...'])`. The failure without it looks like an out-of-funds error deep inside a batch, not like a test-setup problem.

Build it inside the fixture and load it with `loadFixture` so the whole thing is constructed once and snapshotted, not rebuilt per `it`.

## Time-dependent tests and gas snapshots

- **Advancing time**: both mechanisms are in use, and which one is right depends on whose clock the contract under test reads. `MockTime*` contracts (pools, plugins, oracles) expose their own `advanceTime(seconds)` that bumps an internal mock clock, and when a pool and its plugin each track time separately, both need advancing together, e.g. `packages/default-plugin/test/AlgebraPool.gas.spec.ts:91-94`: `await pool.advanceTime(secs); await plugin.advanceTime(secs);`. A contract that reads `block.timestamp` directly has no such clock to bump, and there hardhat-network-helpers' `time.increase` is the right tool — `packages/alm` and `packages/volatility-oracle` both use it. So look for an `advanceTime` method on the mocks already in play first, and fall back to `time.increase` only when there is none; mixing them moves two clocks apart.
- **`[ @skip-on-coverage ]`** appears in several gas-cost test titles across the repo (`packages/default-plugin/test/AlgebraPool.gas.spec.ts`, `packages/dynamic-fee/test/AdaptiveFee.spec.ts`, `packages/volatility-oracle/test/VolatilityOracle*.spec.ts`), signaling "skip this under coverage instrumentation, the gas numbers are meaningless there." It is enforced by a `.solcover.js` carrying `mocha: { grep: '@skip-on-coverage', invert: true }`, and every one of the thirteen packages with tests now ships one, so the tag does what it says everywhere. `packages/volatility-oracle` greps `'@skip-on-coverage|@slow'` because its `.solcover.js` replaces the mocha section of its `hardhat.config.ts` wholesale. If you add tests to a package that somehow lacks the file, copy `packages/alm/.solcover.js`; the tag alone will not make `npx hardhat coverage` skip anything.
